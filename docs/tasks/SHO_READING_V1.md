# SHO_READING_V1 — 笙の重ね字2箇所と手移りだけを確定する

2026-10-01の所有者指示に基づく今回の単一タスク。大きな製品ゴールは `docs/PRODUCT_GOAL_V1.md` に保持するが、今回その全体実装には進まない。

## 目的・対象範囲

**平調・五常楽急の笙について、未解決の重ね字2箇所と手移りを一次資料・PD資料から確定し、既存の笙対象区間を完全に検証済みの演奏イベント列にする。**

基準fixtureの笙本体4行×8主拍点、`sho.L1.P1`〜`sho.L4.P8`の32箇所と、その範囲内に必要な合竹・手移りを対象とする。未解決の重ね字は `sho.L3.P6`（第三行第六拍点）と `sho.L4.P3`（第四行第三拍点）。32は主拍点数であり、展開後の演奏event総数ではない。対象を都合のよい冒頭だけに縮小しない。

初度/二返、止手、篳篥、龍笛、合奏の完成、5/10/20分運用、独奏曲探し、汎用音源改良、Qの再同定には広げない。対象外の既存コードは回帰・依存のため保持するだけで、開発課題を増やさない。本体区間の末尾を止手・正式終止へ読み替えない。

## 継続する既存資料と現在地

起点は既存開発commit `96223889106fa98c85a52d2f08ba8d04f186fb9d`。移行manifestの出典とファイルhashを参照する。

- `features/gagaku/product/score-reading.md`: 調査済み箇所と未確認点。以前の「1932 c5–6が凡例」は訂正済みなので、その探索をやり直すだけで終えない。
- `score-fixture.json`: 元記号・音高・bbox・仮の演奏指定。既存の`preview_design`をverifiedに書き換えるだけでは完了しない。
- `score-sources.json`, `score-evidence.json`, `score-review.json`: 版・画像URL/hash・過去の検証記録。
- `rights.json`, `status.json`: 制作経路と製品状態。過去の検査結果を今回の実施済み結果へ流用しない。
- 笙30合竹の記号/音高照合、2箇所未読、手移り・拍内配置未検証という出発点を保持する。既存192秒音声では未読を無音にしており、完成した演奏ではない。

### 優先一次資料

1. 雅楽講究会1932『鳳笙譜 初之巻』: https://dl.ndl.go.jp/pid/1192407 。既存記録のc7右（印刷2）の合竹表、c14左端（印刷17）・c15右（印刷18）の五常楽急を確認する。隣の曲を混ぜない。
2. 東儀文礼1894『雅楽集 鳳笙譜』: https://dl.ndl.go.jp/pid/855853 。既存記録のc11–12の合竹表、c13–14の吹吸生気替手移図、c30右（印刷21）の同曲を照合する。

ページ番号は既存調査の案内であり、実画像で該当箇所を再確認する。読みが足りない場合だけ、同書の凡例・他箇所・別版のPD/一次資料へ対象を絞って探索する。別版を無条件に同一視せず、規則の適用範囲と版差を記録する。

## 実行手順

1. 最初に基準fixtureの対象32箇所と範囲内の遷移を列挙し、今回の対象・未知点を固定する。対象eventの必要総数は合竹/手移りを展開して算出し、未確定ならnullと理由を残す。
2. 2箇所の全体画像と拡大部分、別版の対応部分を確認し、上下の字・添字・奏法指示の関係を判定する。OCRだけで確定せず、重ね字を単一の普通合竹に潰さない。
3. 範囲内の各手移りについて、必要な発音管、残す/外す/加える管、その順序と記譜上の相対タイミングを一次資料へ対応させる。始点と終点の集合差だけで伝統的な順序が確定したとしない。
4. `原資料ID/版/ページまたはcanvas/bbox → 原記号 → 読解規則 → 合竹・手移り → event ID` を保存する。既存の転記とは別途元譜照合を行い、fixtureとコードの自己一致だけを根拠にしない。
5. 既存プレビュー・過去結果を基準として保存し、検証済みの笙専用event列を別版にする。相対拍位置・奏法が未確認なら完全検証eventに数えない。秒換算テンポやgainの自前指定は読解上の事実と分離し、史実として認証しない。
6. 既存の自前物理音源で笙stemだけを再生成する。合竹ごとの機械的な切断・一律クロスフェードを、資料で確定した手移りの代用にしない。必要な笙専用スケジューリングは実装してよいが、他管や演奏全体へ拡張しない。
7. 回帰テストと、このタスクの元資料対応・event被覆・手移り順序・欠落/重複/NaN/クリッピング・出典欠落拒否の検査を実行する。既存の未読fixtureを前提にするテストはそのfixtureを凍結して維持し、合格させるために削除しない。CIで実際に生成した笙WAV・event・検査結果・hashをartifact化する。

## タスクの完了条件

次を同じcommitとartifactで満たした場合だけ `TASK_COMPLETE`。

- 対象区間の未読記号0。
- 必要な合竹・手移りすべてがsource location付きで定義される。
- 必要総event数と完全検証済みevent数を明示し、両者が一致する。主拍点32や音高確認だけをevent完了数へ置き換えない。
- 笙stemを再生成し、旧プレビューと新成果を区別して再生成コマンド・入力/音声/ソースhashを保存する。
- 回帰テストと対象タスクのCIがPASS。CI成功だけで原譜読解正解を保証したと扱わない。
- 新repoのこのタスクIssueと対応PRに、根拠、event数、笙stem、検査結果、未確認点の有無を記録する。

**タスク完了後は停止する。次の楽器・反復・止手・運用へ自動で進まない。** 本タスクが完了しても製品全体のR/M/A/E/P/UをすべてPASSにしない。全体の試聴Uを今回の完了要件として追加しない。

## 公開資料で確定できない場合

推測や聴感で補完せず、このタスクを `BLOCKED_PUBLIC_EVIDENCE` として停止する。以下を残す。

- 判定できないcell/transition/event IDと、具体的に欠ける情報。
- 確認した版・箇所、探索先、得られた記述と、解消しなかった理由。
- 複数の読解候補がある場合、その差と識別に必要な情報。候補をverifiedにしない。
- 確定できた範囲と、完全検証event数/必要総数。必要総数不明は不明のままにする。
- 新規実器測定・新規録音を提案して実行へ移さない。他課題に切り替えて作業を継続しない。

不足の具体化による停止は、本プロジェクト一般が不可能という結論とは別である。
